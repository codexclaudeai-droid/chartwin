# Chart Service Policy Rules

## 1. Purpose

이 문서는 TradingCore TC Chart 서비스의 내부 운영정책 기준을 고정한다.

적용 범위:

- 무료체험 신청, 재신청, 연장
- 구독 신청, 입금 확인, 구독 승인
- 구독 취소, 환불, 반려
- 관리자 설정값과 실제 동작의 매핑

이 문서는 공개 약관 문구가 아니라 관리자와 개발자가 동일한 기준으로 운영/구현/QA를 진행하기 위한 내부 규정이다.

## 2. Source of Truth

정책 동작의 구현 기준:

- 무료체험 신청/연장: `src/server/chart-service/async-service.ts`
- 무료체험 정책 API: `app/api/admin/trial-policy/route.ts`
- 무료체험 정책 관리자 화면: `app/admin/admin-trial-policy-panel.tsx`
- 회원별 무료체험 예외 설정: `app/admin/user-admin-panel.tsx`
- 구독 승인/취소/환불 도메인 전이: `src/domain/chart-service/subscriptions.ts`
- 결제 확인/반려/환불 도메인 전이: `src/domain/chart-service/payments.ts`

정책 변경 시 위 구현 파일과 이 문서를 함께 갱신한다.

## 3. Free Trial Policy

### 3.1 Default Trial

기본 무료체험은 관리자 무료체험 정책의 `기본 무료체험 일수`를 사용한다.

- 기본값은 7일이다.
- 관리자가 값을 변경하면 신규 무료체험 신청의 종료일과 안내 문구는 변경된 일수를 사용한다.
- 무료체험 신청 성공 응답은 실제 적용 일수인 `durationDays`와 종료일인 `endsAt`을 포함한다.

### 3.2 Eligible User

무료체험 자동 신청은 일반회원 계정만 가능하다.

| 사용자 상태 | 처리 |
| --- | --- |
| 비로그인 | 로그인/회원가입 안내 |
| 일반회원 | 무료체험 신청 가능 |
| 관리자 또는 기타 비일반회원 | 신청 불가 |
| 이미 전체 차트 접근권한이 있는 유료 구독자 | 이미 활성 상태로 안내 |

### 3.3 One-Time Limit

무료체험은 계정당 1회를 기본 원칙으로 한다.

무료체험 이력으로 판단하는 데이터:

- 무료체험 사용 기록
- 기존 구독 상태가 `trial_requested`, `trial_active`, `trial_expired` 중 하나인 경우

무료체험 이력이 있고 예외 정책이 없으면 재신청은 거절한다.

## 4. Free Trial Exception Priority

무료체험 재신청 또는 연장 예외는 다음 우선순위로 적용한다.

| 우선순위 | 예외 정책 | 조건 | 적용 기간 | 소모 여부 |
| --- | --- | --- | --- | --- |
| 1 | 회원별 재신청 가능 횟수 | 회원 상세에서 남은 횟수 `remainingCount > 0` | 현재 유효 무료체험 정책의 적용 일수 | 1회 차감 |
| 2 | 이벤트 재신청/연장 허용 | 이벤트 정책 사용, 이벤트 기간 안, 재신청 허용 체크 | 이벤트 무료체험 일수 또는 기본 무료체험 일수 | 차감 없음 |
| 3 | 예외 없음 | 무료체험 이력 있음 | 적용 없음 | 거절 |

회원별 예외는 전역 이벤트 정책보다 먼저 적용한다.

## 5. Free Trial Extension Rules

이미 무료체험 중인 회원이 다시 무료체험 신청 버튼을 누른 경우:

| 조건 | 처리 |
| --- | --- |
| 무료체험 기간이 남아 있고 예외 없음 | "이미 무료체험 적용 중" 안내, 기존 종료일 표시 |
| 무료체험 기간이 남아 있고 회원별 예외 있음 | 기존 종료일 기준으로 추가 기간 연장 |
| 무료체험 기간이 남아 있고 이벤트 재신청/연장 허용 | 기존 종료일 기준으로 추가 기간 연장 |
| `trial_active` 상태지만 종료일이 지남, 예외 없음 | 재신청 거절 |
| 종료된 무료체험 회원, 회원별 예외 있음 | 신청 시점 기준으로 새 무료체험 기간 적용 |
| 종료된 무료체험 회원, 이벤트 재신청 허용 | 신청 시점 기준으로 새 무료체험 기간 적용 |

연장 계산 기준:

- 기존 종료일이 신청 시점보다 미래이면 `기존 종료일 + 적용 일수`
- 기존 종료일이 없거나 이미 지났으면 `신청 시점 + 적용 일수`

연장 시 새 구독 레코드를 만들지 않고 기존 무료체험 구독의 `endsAt`을 갱신한다.

## 6. Free Trial Records and Notifications

무료체험 신규 신청 또는 연장 시 다음 기록을 만든다.

- 무료체험 사용 기록
- 사용자 알림
- 고객센터 비공개 문의 기록

이미 무료체험 중이고 예외가 없어 안내만 하는 경우에는 새 사용 기록이나 고객센터 문의를 만들지 않는다.

안내 문구 기준:

- 이미 이용 중: 실제 적용 일수와 종료 예정일을 표시한다.
- 신규 신청: 실제 적용 일수와 종료 예정일을 표시한다.
- 신청 전 확인창: 정책값을 사전에 조회하지 않는 화면에서는 특정 숫자 대신 "설정된 기간"이라고 표현한다.

## 7. Subscription Request Policy

구독 신청은 사용자가 플랜과 결제수단을 선택한 뒤 생성된다.

중복 신청 방지 대상 상태:

- `payment_pending`
- `payment_requested`
- `active`
- `expiring`
- `cancel_requested`
- `refund_requested`

위 상태의 기존 구독이 있으면 새 구독 신청을 막고 마이프로필에서 구독내역 확인을 안내한다.

## 8. Manual Payment and Activation Policy

결제와 구독 활성화는 관리자 확인을 기준으로 한다.

기본 흐름:

1. 사용자가 플랜을 선택한다.
2. 사용자가 결제수단과 결제 정보를 입력한다.
3. 서버가 결제요청과 구독요청을 생성한다.
4. 관리자가 입금 또는 USDT 수신을 확인한다.
5. 관리자가 입금확인을 처리한다.
6. 관리자가 구독승인을 처리한다.
7. 구독 상태는 `active`가 되고, 구독승인 일시를 시작일로 기록한다.
8. 종료일은 구독승인 일시 + 플랜 기간으로 계산한다.

입금확인과 구독승인 사이의 대기시간은 이용 기간에 포함하지 않는다.

가매출 처리:

- 관리자가 가매출 입금확인을 선택하면 결제 확인과 구독 활성화를 한 번에 처리할 수 있다.
- 가매출은 입금확인과 구독승인이 같은 시점에 처리되는 예외 흐름이므로 해당 처리 시점을 시작일로 본다.
- 가매출 처리 시 관리자 메모에는 가매출 문구를 남긴다.

## 9. Cancellation and Refund Policy

회원은 마이프로필에서 활성 구독의 취소 또는 환불을 요청할 수 있다.

요청 가능 상태:

- `active`
- `expiring`

상태 전이:

| 요청 | 사용자 요청 후 | 관리자 승인 후 | 관리자 반려 후 |
| --- | --- | --- | --- |
| 취소 | `cancel_requested` | `cancelled` | `active` |
| 환불 | `refund_requested` | `refunded` | `active` |

환불 승인 시:

- 관련 결제요청은 `refunded`가 된다.
- 관련 추천포인트 ledger는 `reversed`가 된다.
- 감사로그를 남긴다.

취소 승인 시:

- 구독 상태는 `cancelled`가 된다.
- 차트 접근권한은 제거된다.
- 감사로그를 남긴다.

## 10. Profile Display Policy

마이프로필의 구독 서비스 개요는 현재 구독 상태와 종료일을 표시한다.

표시 기준:

- 시작일이 있으면 시작일 표시
- 종료일이 있으면 만료일 표시
- 종료일이 있으면 `서비스종료 D-N` 카운터 표시
- 종료 당일은 `D-Day`
- 종료일이 지난 경우 `D+N`

## 11. Admin Setting Map

| 관리자 화면 | 설정값 | 실제 동작 |
| --- | --- | --- |
| 무료체험 정책 > 기본 무료체험 일수 | `baseDurationDays` | 신규 무료체험 기본 일수, 이벤트 일수가 비어 있을 때 적용 일수 |
| 무료체험 정책 > 이벤트 무료체험 일수 | `eventDurationDays` | 이벤트 기간 안에서 재신청/연장 시 적용 일수 |
| 무료체험 정책 > 이벤트 시작/종료 | `eventStartsAt`, `eventEndsAt` | 이벤트 활성 기간 판단 |
| 무료체험 정책 > 이벤트 정책 사용 | `eventEnabled` | 이벤트 정책 사용 여부 |
| 무료체험 정책 > 재신청 및 기간 연장 허용 | `eventAllowReapply` | 이벤트 기간 중 만료 회원 재신청 및 이용 중 회원 기간 연장 허용 |
| 회원 상세 > 무료체험 재신청 가능 횟수 | `remainingCount` | 회원별 예외 횟수, 사용 시 1회 차감 |
| 회원 상세 > 무료체험 재신청 허용 메모 | `note` | 운영 메모, 정책 판단에는 사용하지 않음 |

## 12. QA Checklist

- [ ] 기본 무료체험 일수를 변경하면 신규 신청 종료일과 안내 문구가 변경된다.
- [ ] 무료체험 중인 회원이 예외 없이 재신청하면 기존 종료일 안내만 표시된다.
- [ ] 무료체험 중인 회원에게 회원별 예외 횟수를 주면 기존 종료일 기준으로 연장된다.
- [ ] 무료체험 종료 회원에게 회원별 예외 횟수를 주면 신청 시점 기준으로 재신청된다.
- [ ] 이벤트 재신청/연장 허용 시 이벤트 기간 안에서만 재신청 또는 연장된다.
- [ ] 이벤트 무료체험 일수가 비어 있으면 기본 무료체험 일수를 사용한다.
- [ ] 회원별 예외와 이벤트 예외가 동시에 있으면 회원별 예외가 먼저 소모된다.
- [ ] 예외 없는 무료체험 이력 회원은 재신청이 거절된다.
- [ ] 활성 구독자는 새 구독 신청이 중복 생성되지 않는다.
- [ ] 취소/환불 승인 및 반려는 감사로그와 알림을 남긴다.
